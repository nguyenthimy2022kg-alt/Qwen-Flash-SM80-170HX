# Qwen-Flash-SM80

**面向双 SM80 显卡的 Qwen3.8-Flash-Next 社区 vLLM 运行方案。**

结合 **GDS（SSD 数据直接进入显存）**、**TEP2（两卡张量切分与专家分工）**、**MTP6（每轮最多提前猜六个片段）**和针对实际形状编写的计算内核，在双 CMP 170HX 上运行主模型 NVFP4 与磁盘 PLE（模型附加的大型查表数据）。

本机最新一次“写个网站网页”长输出：**平均 decode（逐步生成）170.826 tok/s（每秒生成片段数）**，输出 29,010 个片段并自然结束。

这是针对特定模型、版本和双卡硬件整理的社区方案，与通用上游 vLLM 的安装包有所不同。已验证硬件为双 CMP 170HX（SM80、每卡约 63.39 GiB 显存）；不把结果直接推广到所有 A100、其他 SM80 卡或其他模型。

## 做了哪些优化

| 已采用的优化 | 通俗说明 | 已有结果 |
|---|---|---|
| GDS＋PLE 接入 | 查表数据从 SSD 进入显存，减少 CPU 中转，并按模型输入正确交接数据 | 完成数据及生命周期接入；没有单独的整模型提速比例 |
| C++ 读取计划器 | 用本地代码整理读取任务，减少 Python 列表和对象处理 | 历史 4096 行规划约 8.655→1.188 ms；是局部结果 |
| 常驻读取线程、固定缓冲区 | 读取资源提前创建、循环使用，不在每步重新建立 | 保留 32 个读取线程、3 个暂存槽位 |
| 同进程异步读取与交接修复 | 后台读取与计算重叠，避免跨进程等待及输入提前复用 | 历史组合版本 51.33→66.74 tok/s；并非单项独立收益 |
| TEP2 与双卡直接通信 | 两卡共同处理模型，同时分担专家，保留 P2P（显卡间直接传输） | 早期 MTP6 各五轮汇总：TEP2 131.044、TP2 127.820 tok/s |
| HC 单行矩阵计算 | 为 HC（多路状态混合）的单行输入使用专用 GEMV（矩阵与向量相乘） | 当时 TP2 对照 74.55→80.02 tok/s |
| TileLang 输入投影 | 针对单行 QKVZ/BA（注意力与递推模块的输入变换）合并计算，直接使用原缓冲区 | 已进入运行版本；不单独承诺可叠加的整体百分比 |
| CUDA Graph 与已有融合算子 | 预先录制并重放 GPU 计算，减少逐项安排计算的开销 | 当前保留整体计算图与原有 MTP GDN 融合路径 |
| MTP6＋七行 PLE 行号规划 | 一轮验证多个草稿片段，用 NumPy 快路径整理对应查表行号 | 整理版历史五轮汇总 131.044；行号规划版随后一次 158.013 tok/s |
| 全词表 INT8 草稿打分＋原精度复核 | 保留全部词，先用压缩权重打分，每卡前 32 词用 BF16（原数值格式）复核，再汇总最佳词 | 最新一次 170.826 tok/s；历史前版一次 158.013，观察高约 8.1% |
| 加载内存保护 | 限制容器内存，主机可用内存过低时停止自有服务 | 保留加载修复与保护，不把加载速度等同于生成速度 |

表中记录来自不同阶段和条件，**不能相加或相乘**。最新 INT8 与历史版本的输出内容不同，8.1% 是观察差异，不能全部归因于量化，也不保证每个请求相同。[查看完整测试条件](docs/性能记录.md)。

## 快速开始

```bash
git clone https://github.com/nguyenthimy2022kg-alt/Qwen-Flash-SM80.git
cd Qwen-Flash-SM80
```

需要 Linux、Docker、NVIDIA Container Toolkit、兼容 CUDA 13 的驱动，以及正常工作的 GDS/cuFile 与 GPU P2P。两卡合计显存和 SSD 数据布局必须满足当前模型要求。`allow_compat_mode=false`：GDS 不可用时不会静默退回主机中转。

1. 准备含 MTP 权重的对应 NVFP4 模型，以及 **FP8 PLE 检查点和 GDS 数据**。仓库不包含模型权重。[数据准备说明](docs/使用说明.md#模型与-ple-数据)
2. 构建固定上游版本的镜像：

   ```bash
   docker build -t qwen-flash-sm80:0.1.1 .
   ```

3. 复制并编辑配置，把模型父目录、模型子目录、PLE 目录和显卡编号换成自己的：

   ```bash
   cp config/example.json config/local.json
   ```

4. 按使用说明登记 PLE 数据身份后，检查启动命令，再启动：

   ```bash
   python3 scripts/serve.py start --config config/local.json --dry-run
   python3 scripts/serve.py start --config config/local.json
   ```

默认仅监听本机 `127.0.0.1:18420`，模型名 `qwen3.8-flash-next`，提供 OpenAI 兼容接口。首次启动包括编译和模型预热。启动器打印的是任务已提交，模型是否就绪请检查容器日志。

停止时使用启动器打印的容器名：

```bash
python3 scripts/serve.py stop --name <容器名>
```

## 仓库内容

- `src/`：相对固定上游的运行源码，包括 GDS、HC、TileLang 和草稿 INT8。
- `csrc/`：GDS 读取扩展的 C++ 源码；构建时生成本机扩展。
- `src/preload/`：该固定 SM80 环境使用的 Triton 预加载内核和 SHA256 清单，约 17 MB，不含模型权重。
- `patches/`：上游源码校验值与来源分类，防止误覆盖其他版本。
- `config/`、`scripts/`：中文配置说明、启动/停止、数据准备及构建入口。
- `docs/`：已采用优化、性能数据与使用范围。公开文档仅提供中文版本。
