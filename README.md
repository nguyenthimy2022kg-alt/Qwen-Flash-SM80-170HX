# Qwen-Flash-SM80 / CMP 170HX

**简体中文** | [English](README.en.md)

**面向双 SM80 显卡的 Qwen3.8-Flash-Next 社区 vLLM 运行方案。**

使用 **GDS 直读 SSD**、**TEP2 双卡并行**、**MTP6 推测生成**及专用内核，在双 CMP 170HX 上运行 NVFP4 主模型。约 51.2 GB 的 PLE 查表数据留在 SSD，按需读入显存。

**v0.3.0：支持 1～10 并发，示例配置默认 10 并发。** NVIDIA 官方 NVFP4 权重，统一使用 MTP6；新增多请求草稿隔离、紧凑词表通信和多请求 PCIe 通信优化，已移除历史文本复制草稿。

**双 CMP 170HX 十并发实测：合计 749.67 tok/s，每路平均 76.29 tok/s。**

[开始部署](docs/从零部署.md) · [十并发测速](#十并发测速) · [API 接入](#api-接入) · [版本验证](docs/MULTI_REQUEST.md)

验证硬件为双 CMP 170HX（SM80，每卡约 64 GiB 显存）。部署前需准备好 GPU P2P 和 NVMe GDS；已有 NVIDIA 模型及配套 PLE 数据可直接复用，重新构建镜像即可升级。

## 项目特点

- **SSD 直通显卡**：通过 GDS/cuFile 按需读取 PLE 查表数据，数据本体无需经过 CPU 内存中转，并将读取与模型计算重叠。上游已有 PLE CPU 内存卸载；本项目在固定上游版本上增加了这条 SSD → GPU 直通路径。
- **减少约 47.68 GiB 的整表显存需求**：约 **51.2 GB** 的 FP8 PLE 表保存在 SSD，无需整表常驻显存，也无需整表常驻主机内存；显存只保留所需数据与工作缓冲区。容量按一整份表计算，不是每张卡各省 47.68 GiB。
- **从约 38 提升到 170.826 tok/s**：相当于初始部署的 **4.50 倍，吞吐量提升约 350%**；代码较多的实测场景可接近 **200 tok/s**。这是项目不同阶段的历史对比，并非同条件原版 vLLM 对照。[数据与说明](docs/性能记录.md)

## 十并发测速

**2026-10-11，NVIDIA 官方 NVFP4，双 CMP 170HX，TEP2＋MTP6。** 提示词为“写个网站网页”，关闭思考，`temperature=1`、`top_p=0.95`、`top_k=20`，10 路各输出 5,000 tokens。

| 指标 | 结果 |
|---|---:|
| 合计输出速度 | **749.67 tok/s** |
| 每路平均输出速度 | **76.29 tok/s** |
| 每路速度范围 | 75.19～78.30 tok/s |
| 总输出量 | 50,000 tokens |
| 每轮生成计算 | 72.34 ms |

输出速度按第一个至最后一个非空流式输出计时，不计首字等待。本轮从优化前的 **623.41 tok/s** 提升至 **749.67 tok/s**，合计提高约 **20.3%**。[优化过程与测试记录](docs/MULTI_REQUEST.md)

## 历史 8K～128K 测速

以下为 2026-09-08 使用 RadixArk 权重的历史结果。任务提示词：**“写个网站网页”**，前置网页设计参考资料填充输入长度。**开启思考，使用模板默认 xhigh（最高档），未单独限制思考预算**；TEP2＋MTP6，输出上限 50,000 token，每档一轮，均自然结束。思考内容与正文均计入输出。

| 输入长度 | Prefill 速度*（tok/s） | Decode 速度（tok/s） |
|---|---:|---:|
| 8K | 1986.38 | **168.29** |
| 16K | 2083.10 | **152.99** |
| 32K | 2068.85 | **156.44** |
| 64K | 2036.21 | **159.88** |

## 快速开始

按 [部署指南](docs/从零部署.md) 完成三个步骤：准备主机 → 下载并转换模型数据 → 构建并启动服务。模型部署命令和配置集中在该页；仓库不包含模型权重或预构建镜像。

CMP 驱动优先使用已包含 BAR1/P2P 补丁的原始社区项目 **bayley/cmpunlocker**，无需额外叠加本仓库补丁。已有 P2P/GDS 可用的主机可直接进入模型准备。

## API 接入

| 客户端设置 | 值 |
|---|---|
| OpenAI 兼容 Base URL | `http://127.0.0.1:18420/v1` |
| 完整聊天请求地址 | `http://127.0.0.1:18420/v1/chat/completions` |
| 模型名 | `qwen3.8-flash-next` |
| API Key | 留空；客户端强制要求时可填占位值 |

按客户端要求填写 Base URL 或完整地址，二者不要混用。默认仅允许本机访问：手机或另一台电脑上的 `127.0.0.1` 指向它自己。远程接入、请求示例及常见故障见 [部署指南](docs/从零部署.md)。

## 已集成优化

| 优化位置 | 当前实现 |
|---|---|
| SSD → GPU | GDS/cuFile 按需读取 PLE；C++ 规划、32 个常驻线程、3 个缓冲槽和有序异步交接 |
| 双卡计算 | TEP2（张量并行＋专家并行）、Marlin 与 GPU P2P |
| 草稿生成 | 固定 MTP6，各请求独立保存草稿概率，由主模型验证 |
| 草稿打分 | 全词表 INT8 初筛、BF16 候选复核，使用 8 候选概率草稿；猜测和验证使用同一草稿概率 |
| 主模型打分 | 温度 0 传输最佳词；温度 1、top-k 20 时传输候选与并列词，其他配置保留完整词表路径 |
| 小形状计算 | HC GEMV、TileLang 单行投影、七行 HC/GDN 融合、CUDA Graph（录制后重放计算） |
| 双卡通信 | FlashInfer PCIe IPC AllReduce（两卡汇总结果），覆盖 1～10 请求的草稿与主模型验证形状 |
| 多轮缓存 | 36-token 前缀匹配；物理缓存块仍为 3,456 token |
| 主机内存 | 选择性 CUDA 加载、定向内核预热、流式权重准备和内存保护 |
| 稳定性 | PLE 数据交接同步、上下文边界结束修复、采样回退预热 |

当前配置为 **双 SM80、1～10 个活动请求、同步调度**，示例默认 10 并发。各请求共享显存缓存，262K 是每条请求的上下文上限。总上下文上限 262,144 token，默认输出上限同为 262,144，实际输出仍受剩余上下文限制。图片配置上限为 128 张，并不保证任意 128 张图片都能放入上下文和显存。默认保留思考、思考历史和工具解析。

## 仓库内容

- `src/`：相对固定上游的运行源码，包括 GDS、HC、TileLang 和草稿 INT8。
- `csrc/`：GDS 读取扩展的 C++ 源码；构建时生成本机扩展。
- `src/preload/`、`src/memory_extra_preload/`：该固定 SM80 环境使用的 Triton 预加载内核和 SHA256 清单，约 24 MB，不含模型权重。
- `patches/`：上游源码校验值与来源分类，防止误覆盖其他版本。
- `config/`、`scripts/`：配置示例、启动/停止、数据准备及构建入口。
- `docs/`：已采用优化、性能数据与使用范围。提供中英文首页、部署指南、P2P 与 GDS 参考文档；详细历史记录为中文。
