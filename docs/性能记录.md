# 性能记录

记录日期：2026-09-08。本文件包含已加载发布服务的长上下文测速及打包前的历史记录；各节分别注明测试条件。

## 8K～128K 输入与流式输出测速

2026-09-08，复用已加载的发布服务；TEP2、MTP6、GDS、HC、TileLang、完整词表 INT8 草稿打分及 BF16 复核均保持启用。每档串行测试一次，输出上限 **50,000 token**，五档均自然结束。

**思考设置：开启**（`enable_thinking=true`、`preserve_thinking=true`）。本轮请求未显式传入 `reasoning_effort`（思考强度档位），模板默认解析为 **`xhigh`，即该模板支持的最高档**；未单独设置思考预算。本机模板包含 `reasoning_effort|default('xhigh')`，当前服务 `/tokenize` → `/detokenize` 的渲染检查确认注入了 `Reasoning effort is set to xhigh`。官方模型说明也注明默认 xhigh，支持 xhigh / medium / low：[官方说明](https://huggingface.co/Qwen/Qwen3.8-Flash-Next/blob/main/README.md)。思考 token 和正文 token 都计入输出。

**任务提示词：`写个网站网页`。** 为覆盖不同输入长度，在任务前填充网页设计参考资料；完整消息结构为：

```text
以下是网页设计参考资料，可以自行取舍，不需要逐条复述。
<参考资料>
参考记录0：布局采用清晰的信息层级，导航突出主要入口，内容区域控制阅读宽度。
参考记录1：配色保持协调，按钮状态应清晰，浅色和深色背景之间保持可读性。
参考记录2：移动设备上调整栅格列数，图片保持比例，菜单适应较小屏幕。
参考记录3：页面可以包括介绍、功能卡片、作品展示和联系区域，保持内容连贯。
参考记录4：交互提供适当反馈，动画时长适中，表单具有清楚的标签和错误提示。
……按上述五条内容循环，记录编号递增，截取到对应输入长度……
</参考资料>

写个网站网页
```

参考资料按 tokenizer 截取后再加入消息与聊天模板；实际输入长度分别为 8193、16385、32769、65537、131073 token。每档使用独立 `cache_salt`，避免跨请求命中前缀缓存。采样沿用服务设置：`temperature=1.0`、`top_p=0.95`、`top_k=20`、`min_p=0.0`、`presence_penalty=1.5`，未固定随机种子。

| 输入档位 | 思考设置 | Prefill 速度*（tok/s） | 首输出等待（秒） | Decode 速度（tok/s） | 实际输出 token |
|---|---|---:|---:|---:|---:|
| 8K | 开启，默认 xhigh | 1986.38 | 4.12 | **168.29** | 28,134 |
| 16K | 开启，默认 xhigh | 2083.10 | 7.87 | **152.99** | 37,308 |
| 32K | 开启，默认 xhigh | 2068.85 | 15.84 | **156.44** | 27,132 |
| 64K | 开启，默认 xhigh | 2036.21 | 32.19 | **159.88** | 31,032 |
| 128K | 开启，默认 xhigh | 2059.93 | 63.63 | **151.05** | 31,143 |

*Prefill 列采用客户端近似口径：**输入 token 数 ÷ 首输出等待时间**。首输出等待包含服务端排队、输入处理、预填充和首个输出生成，不是单独测得的 GPU prefill 吞吐量。

Decode 采用 **实际输出 token 数 ÷（最后一个非空流式输出到达时间 − 第一个非空流式输出到达时间）**。思考内容与正文均计入；空消息、usage 与结束通知不延长输出耗时。流式片段可能包含多个 token，因此这是客户端接收速度，不是逐 token GPU 计时。

原始流式记录重算的首尾时间与汇总一致，五档结束后服务健康检查通过。每档内容不同、仅测试一次，不将波动归结为单一因素；没有进行生成网页的完整功能验收。机器可读结果：[context-benchmark-20260908.json](context-benchmark-20260908.json)。

## 维护者补充实测：接近 200 tok/s

维护者反馈，在思考较少的网页生成场景下，输出速度可接近 **200 tok/s**。提供的客户端截图显示：

| 指标 | 客户端显示值 |
|---|---:|
| 输出速度 | **199 tok/s** |
| 首字延迟 | **962 ms** |

此记录来自维护者实际使用反馈与客户端截图，未使用上述五档测速脚本重算。截图未显示思考强度设置或思考 token 数，因此不将其标注为 low 档，也不据此认定减少思考必然提高每秒输出速度。

## 打包前的短提示词长输出

硬件：双 CMP 170HX，SM80，每卡约 63.39 GiB 显存。双卡链路受 PCIe 2.0 ×4 限制，既有 P2P 大块带宽约 1.66 GB/s。

环境：vLLM `0.1.dev20073+g8e685d198`，PyTorch 2.13 + CUDA 13.0，Triton 3.7.1，Python 3.12；TEP2、MTP6、GDS、HC、TileLang、七行行号规划，以及完整词表 INT8＋原权重复核。

提示词为 **“写个网站网页”**；temperature=0、seed=0，先做 128 token 预热；正式输出上限 32768，允许自然结束。

| 指标 | 原七行规划版本，历史一次 | INT8＋复核组合，一次 |
|---|---:|---:|
| 平均 decode 吞吐量 | 158.013 tok/s | **170.826 tok/s** |
| 输出 token 数 | 28090 | 29010 |
| 思考 token 数 | 5645 | 4295 |
| 草稿接受率 | 58.116% | 57.646% |
| 每轮生成 token 数，估算 | 4.487 | 4.459 |
| 每轮耗时，估算 | 28.392 ms | 26.097 ms |
| prefill 耗时 | 约 0.219 s | 0.218 s |
| 结束方式 | 自然结束 | 自然结束 |

两次测试的吞吐量差异约为 8.1%。由于输出内容、思考长度和上下文分布不同，该差异不代表固定增益。每轮推进与时间由总量折算，存在首尾误差。这里的 prefill 是短提示词成绩，不代表 8K～64K 输入。

最终服务健康检查通过，HTML 有关闭标签；只检查输出头尾，未进行网页浏览器功能验收。双卡各 580 个历史输入的草稿选词与原路径一致，非单行回退通过对应检查；该检查不覆盖任意输入的严格等价性或完整质量评估。

INT8 只用于单行草稿打分；主模型原 BF16 输出权重和接受规则保持不变。原词表权重仍在，每卡额外压缩权重和缩放约 323 MB。最新运行的 KV 缓存约 9.96/8.56 GiB，计算图约 0.69 GiB/卡。

## 历史性能记录

- 早期 PP2 且不开 MTP 的 GDN 局部计算图：66.00→71.33 tok/s。当前整体计算图/MTP 路径不再把这一旧局部补丁算作独立新增收益。
- 随后的 TP2 HC 单行优化：74.55→80.02 tok/s。
- TEP2＋MTP6 整理版五轮汇总 131.044 tok/s，同期 TP2＋MTP6 五轮汇总 127.820 tok/s。
- 七行行号规划版一次 158.013 tok/s；随后全词表 INT8＋复核组合一次 170.826 tok/s。

以上记录的配置与输出不同，不能直接计算累计加速比。早期约 37～38 tok/s 的记录未作为当前版本相对上游 vLLM 的对照基线。
