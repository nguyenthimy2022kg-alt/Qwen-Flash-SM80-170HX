# v0.3.0 多请求优化

**简体中文** | [English](MULTI_REQUEST.en.md) · [返回首页](../README.md)

支持 1～10 个活动请求，统一使用 MTP6，保留 GDS、TEP2、前缀缓存、工具调用和图片输入。历史文本复制草稿已移除。

## 配置

按[部署指南](从零部署.md)构建 `qwen-flash-sm80:0.3.0`，在完整的 `config/local.json` 中使用：

```json
{
  "image": "qwen-flash-sm80:0.3.0",
  "max_num_seqs": 10,
  "gpu_memory_utilization": 0.93
}
```

`max_num_seqs` 可设为 1～10，省略时为 1；仓库示例设为 10。各请求共享显存缓存，最大上下文 262,144 不代表十路都能同时占满。保持同步调度和 `draft_int8=true`。

## 改进与速度

2026-10-11 PDT，双 CMP 170HX、NVIDIA 官方 NVFP4 权重、TEP2、MTP6。提示词“写个网站网页”，关闭思考，temperature=1、top-k=20、top-p=0.95，十路各生成 5,000 tokens。

| 阶段 | 每路平均 tok/s | 合计 tok/s | 每轮生成计算 |
|---|---:|---:|---:|
| 本轮优化前 | 63.43 | 623.41 | 87.73 ms |
| 加入紧凑词表通信 | 71.54 | 700.98 | 76.88 ms |
| 加入多请求 PCIe 通信（本版） | **76.29** | **749.67** | **72.34 ms** |

- **多请求草稿隔离**：每条请求保存自己的候选和概率；请求结束、补位和取消后仍按正确的请求身份验收草稿。
- **词表通信**：温度 0 时只交换最佳词；温度 1、top-k=20 时交换候选及并列词信息。后者每卡 70 行载荷从约 16.58 MiB 降到 1.05 MiB，仍由原采样流程执行全局过滤和验收。其他参数组合使用完整词表路径。
- **PCIe 通信**：扩展已有共享显存通信到 1～10 请求的形状。70 行局部对照为 265.45→227.41 µs，10 行为 45.54→34.83 µs；每卡工作区约增加 1.63 MiB。

输出速度按首个至最后一个非空输出计时，不计首字等待；固定长度测试使用 `ignore_eos=true`。词表前后在同一模型加载中比较，PCIe 结果来自紧接着的下一次加载。表格是每种配置的一轮筛选，带相同阶段计时；阶段时间不与两卡时间相加。

## 已完成的检查

| 范围 | 结果 |
|---|---|
| 1～10 请求位置、草稿概率与生命周期 | 通过局部检查和模型请求检查 |
| 温度 0 词表路径 | 双卡局部检查；每卡 7,140 行真实前向最佳词核对通过 |
| 温度 1 词表路径 | 45 组局部案例；每卡 8,318 行真实分数、采样与草稿接受数量核对通过 |
| PCIe 路径 | 20 种形状、5 类回退、非连续输入、独立输出、150 次交错重放通过 |
| 最终 PCIe 模型轮次 | 50 条完整文本/JSON请求、2 次主动取消；13 项口令/JSON精确核对通过 |
| 并发变化 | 活动请求经历 10→1→0；独立追问、取消后补位及结构化恢复完成 |
| 运行文件 | 干净构建的 595 个运行文件与清单一致，测试诊断模块已去除 |

最终 PCIe 轮次另有 1 条 HTTP 200、正常流结束、`finish_reason=tool_calls` 的响应，不符合首版文本脚本的结束断言；原记录保留，补完其余检查后通过。没有把它计入纯文本测速。

本版验证覆盖上述短期文本及请求生命周期；十路满上下文、并发多模态和长期压力尚未在本版复测。2026-10-14 发布整理只运行 CPU 检查和文件校验，没有重新启动模型或使用 GPU。
