# 从零部署

**简体中文** | [English](DEPLOYMENT.en.md) · [返回首页](../README.md)

本文从准备好的 Linux 主机开始，依次完成模型下载、数据转换、镜像构建和服务接入。适用于当前双 SM80 配置；驱动、Docker、GPU P2P 和 GDS 需先按下述要求准备。命令除克隆仓库和远程 SSH 转发外，均在服务主机的仓库根目录执行。

[环境与容量](#环境与容量) · [下载与检查](#1-下载源码与模型) · [转换数据](#3-转换并登记-gds-数据) · [构建与配置](#4-构建与配置) · [启动与接入](#5-启动与接入) · [排错](#常见启动问题)

## 环境与容量

- Linux x86_64、Git、curl，以及 Python 3.10 或更新版本（含 `venv` 和 pip）。本仓库的数据准备脚本仅依赖 Python 标准库；下载工具单独安装到虚拟环境。
- Docker、NVIDIA Container Toolkit，以及兼容 CUDA 13 的驱动。
- 已验证设备为双 CMP 170HX，每卡约 63.39 GiB 显存。两张 40 GB 卡不等价于该配置；其他设备尚未完成整模型验证。
- 测试主机为约 32 GiB RAM 与 8 GiB swap。启动器默认限制容器 RAM 为 21 GiB、RAM＋swap 为 26 GiB；加载时主机还需为其他进程保留空间。
- 模型 safetensors 合计 **135,195,303,851 字节**，GDS 转换额外占用约 **51.2 GB**。建议为模型与转换数据预留至少 **220 GB**；Docker 镜像、构建层和编译缓存另计。
- NVMe、文件系统、驱动与 GPU 拓扑必须支持 GDS；双卡 P2P 需可用。驱动/CMP 支持、PCIe 拓扑与主机 GDS 配置不会由容器自动修复。参考 [NVIDIA GDS 文档](https://docs.nvidia.com/gpudirect-storage/) 与 [Container Toolkit 安装说明](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)。

## 主机验收条件

首次部署先完成以下两项；已经验证可用的主机可直接进入第 1 步。

| 项目 | 配置与通过条件 |
|---|---|
| 双卡 P2P | CMP 设备使用 [bayley/cmpunlocker 的完整 BAR1/P2P 方案](https://github.com/bayley/cmpunlocker/tree/5a7bb4b7e5056306fe49e8b824787659abb19914)，按其 P2P 说明配置驱动并通过实际双向传输校验；无需再叠加本仓库补丁。 |
| SSD 直读显存 | 按 [GDS 配置步骤](GDS_NVME_P2PDMA_REPRODUCTION.md) 安装工具、配置 NVMe P2PDMA，并在禁止 CPU 中转回退时通过数据校验。cmpunlocker 不代替这一步。 |

参考主机为 H12D 主板、单路 EPYC 7532、双 CMP 170HX 和 990 PRO 4TB。SSD 与 GPU **没有接在 PCIe switch 下**；SSD 与读盘卡位于同一 CPU 的同一 PCIe 根总线下、不同根端口。本项目由第一张 GPU 读盘，再通过 P2P 广播给第二张。需要对照插槽时见 [参考硬件与拓扑图](REFERENCE_HARDWARE.md)。

## 1. 下载源码与模型

示例数据目录为 `$HOME/qwen-flash-data`，其中的 `ple-gds` 必须位于通过 GDS 验收的 NVMe 文件系统。若主目录不在合适的磁盘上，请先选定数据目录，并统一替换下文路径及第 4 步配置脚本中的 `root`。已按首页克隆仓库的部署，可跳过以下前两行。

```bash
git clone https://github.com/nguyenthimy2022kg-alt/Qwen-Flash-SM80-170HX.git
cd Qwen-Flash-SM80-170HX
python3 -m venv .venv-hf
.venv-hf/bin/pip install 'huggingface_hub==1.29.0'
mkdir -p "$HOME/qwen-flash-data/models"
```

检查点：[RadixArk/Qwen3.8-Flash-Next-NVFP4](https://huggingface.co/RadixArk/Qwen3.8-Flash-Next-NVFP4/tree/7b719225242aacd3dbd3f9407468c2ee9a9d2594)。固定 revision：`7b719225242aacd3dbd3f9407468c2ee9a9d2594`，另记录于 [`config/model-source.json`](../config/model-source.json)。

该版本已包含主模型 NVFP4 权重、31 个 BF16 MTP 张量，以及 128 个 FP8 PLE 张量和 BF16 scale。无需另行量化 PLE，也无需下载第二个 MTP 检查点。模型按其来源许可证使用。

先查看下载计划，再实际下载：

```bash
.venv-hf/bin/hf download RadixArk/Qwen3.8-Flash-Next-NVFP4 \
  --revision 7b719225242aacd3dbd3f9407468c2ee9a9d2594 \
  --local-dir "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4" \
  --dry-run

.venv-hf/bin/hf download RadixArk/Qwen3.8-Flash-Next-NVFP4 \
  --revision 7b719225242aacd3dbd3f9407468c2ee9a9d2594 \
  --local-dir "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4" \
  --max-workers 2
```

网络中断后可重新执行同一条下载命令。保留完整检查点，包括原 FP8 PLE 分片，以供模型检查和重新转换。此流程直接使用下载目录，不需要历史 `.plefp8.bak` 文件或 `create-gds-fp8-checkpoint-view.py`。

## 2. 检查模型文件

```bash
python3 scripts/check-model.py \
  --model "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4"
```

检查包括固定 config/index 的 SHA256、206 个 safetensors 文件、索引对应张量与文件长度、31 个 BF16 MTP 张量、PLE dtype/shape/scale，以及 tokenizer 文件是否存在。只读取元数据和文件头，不加载 GPU、不读取完整模型权重。输出中的 `weight_payload_sha256_verified: false` 表示未进行权重内容的全量校验。

需要完整下载内容校验时，可单独执行，耗时取决于存储速度：

```bash
.venv-hf/bin/hf cache verify RadixArk/Qwen3.8-Flash-Next-NVFP4 \
  --revision 7b719225242aacd3dbd3f9407468c2ee9a9d2594 \
  --local-dir "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4" \
  --fail-on-missing-files
```

## 3. 转换并登记 GDS 数据

```bash
python3 scripts/prepare-ple.py mapping \
  --index "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4/model.safetensors.index.json" \
  --output "$HOME/qwen-flash-data/ple-mapping.json"

python3 scripts/convert-ple-to-gds-layout.py \
  --checkpoint-index "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4/model.safetensors.index.json" \
  --mapping "$HOME/qwen-flash-data/ple-mapping.json" \
  --output "$HOME/qwen-flash-data/ple-gds" --compact --block-rows 256

python3 scripts/prepare-ple.py enroll \
  --artifact "$HOME/qwen-flash-data/ple-gds" \
  --output config/local-ple-identity.json
```

转换以流式方式复制 PLE 数据，不需要把约 51.2 GB 的表完整放入 RAM。`enroll` 默认重读生成数据进行校验，并将该数据版本记录到 `config/local-ple-identity.json`；首次部署保留默认校验。映射与身份配置不会覆盖已有同名文件，已有且校验通过的数据可继续使用，无需每次启动重新转换。

## 4. 构建与配置

```bash
docker build -t qwen-flash-sm80:0.1.4 .
```

镜像需自行构建，没有发布预构建镜像。以下配置初始化仅用于首次部署；已有 `config/local.json` 时跳过此代码块，直接编辑本机配置中的路径和镜像标签。

```bash
cp -n config/example.json config/local.json
python3 - <<'PY'
import json
from pathlib import Path
p = Path('config/local.json')
c = json.loads(p.read_text())
root = Path.home() / 'qwen-flash-data'
c['models_root'] = str(root / 'models')
c['model_subdir'] = 'Qwen3.8-Flash-Next-NVFP4'
c['ple_artifact'] = str(root / 'ple-gds')
p.write_text(json.dumps(c, ensure_ascii=False, indent=2) + '\n')
PY
```

检查 `config/local.json` 中的 `gpu_ids`；默认 `0`、`1`，也支持完整 GPU UUID。第一张卡为 PLE 读取卡，宜结合 SSD/GPU 拓扑选择。模型、PLE 和身份配置路径应分别对应前几步的产物。配置路径以仓库根目录解析；`models_root` 应包含模型和符号链接目标的共同父目录，容器只能访问挂载范围内的文件。

| 必需配置 | 填写内容 |
|---|---|
| `image` | 与构建命令一致的镜像标签 |
| `models_root` / `model_subdir` | 模型父目录 / 模型目录名 |
| `ple_artifact` | 第 3 步转换目录，包含 `CURRENT` |
| `ple_identity` | 第 3 步生成的 `config/local-ple-identity.json` |
| `gpu_ids` | 两张不同 GPU 的编号或完整 UUID，第一张负责读盘 |

默认启用 TEP2、MTP6、全词表草稿 INT8＋BF16 复核，保留完整 BF16 草稿权重即可。主机 RAM 默认限额 21 GiB、RAM＋swap 总限额 26 GiB，可用 RAM 低于 2 GiB 时停止服务。可选设置见 [配置参考](使用说明.md#配置与启动)。

## 5. 启动与接入

```bash
python3 scripts/serve.py start --config config/local.json --dry-run
python3 scripts/serve.py start --config config/local.json
```

`--dry-run` 校验配置并读取显卡标识后打印命令，不加载模型，也不检查数据文件是否存在。正式启动还检查必填路径、文件/目录类型、Docker 服务、本地镜像和容器重名；它不会代替第 2 步的模型完整性检查，也不会提前证明 P2P/GDS 可用。

启动器返回容器名和 `runs/<容器名>/` 日志目录。首次加载需编译和预热，可用 `docker logs -f "<容器名>"` 查看进度。启动提交不等于服务就绪，待以下接口返回 HTTP 200 后再发送请求：

```bash
curl --fail http://127.0.0.1:18420/health
curl --fail http://127.0.0.1:18420/v1/models
```

| 客户端配置 | 值 |
|---|---|
| 协议 | OpenAI 兼容 |
| Base URL | `http://127.0.0.1:18420/v1` |
| 完整聊天请求地址 | `http://127.0.0.1:18420/v1/chat/completions` |
| 模型 | `qwen3.8-flash-next` |
| API Key | 未配置认证；客户端必填时可填 `local` |

流式请求示例：

```bash
curl --no-buffer --fail-with-body http://127.0.0.1:18420/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next","messages":[{"role":"user","content":"写个网站网页"}],"max_tokens":50000,"stream":true}'
```

服务默认开启思考，使用模板默认 `xhigh` 档。客户端需处理思考与正文输出；`max_tokens` 是两者合计的输出上限，不是目标长度。收到流式内容并正常结束后，才完成实际生成请求验证。测速口径和采样条件见 [性能记录](性能记录.md)。

以上地址使用默认端口 18420；修改 `port` 后需同步修改客户端地址和转发端口。端口仅绑定本机，异机客户端可在客户端机器执行 SSH 转发：

```bash
ssh -N -L 18420:127.0.0.1:18420 用户名@服务主机
```

随后在客户端机器使用相同 Base URL。容器内客户端的 `127.0.0.1` 指向自身，需自行配置到宿主机的网络路径。

### 停止与回退

```bash
python3 scripts/serve.py stop --name "<容器名>"
```

停止器只操作带有本项目标签的容器。修改配置后需重新启动；默认自动生成新的容器名。将 `draft_int8` 设为 `false` 可回退到原 BF16 草稿完整词表打分路径，保留 MTP6 和其他优化；`mode=tp2` 则关闭专家并行。

## 常见启动问题

| 现象 | 排查位置 |
|---|---|
| `POST /v1` 返回 404 | 客户端可能要求填写完整 `/v1/chat/completions` 地址 |
| 找不到模型或 PLE 文件 | 下载是否完整、`model_subdir` 与挂载路径、PLE 转换与登记是否完成 |
| 提示映射或身份配置已存在 | 已校验的数据无需重新准备；确需生成新版本时使用新文件名，并更新配置中的对应路径 |
| 固定模型版本不一致 | 是否使用了指定 revision，是否手动修改过 config/index |
| cuFile/GDS 注册或读取失败 | 主机 GDS、文件系统和拓扑；当前 `allow_compat_mode=false` 不使用主机中转回退 |
| 停止后生成 `memory-stop.txt` | 主机可用 RAM 触发保护，先检查其他进程与 swap 配置 |
| 提示 image 不存在 | 先执行 Docker 构建，确认 image 标签与 `config/local.json` 一致 |
| 无法访问 Docker | 检查 Docker 服务是否运行，以及当前用户是否有访问权限 |
| `/health` 尚未返回 200，或容器未创建 | 查看 `runs/<容器名>/supervisor.log`、`error.txt` 和 `docker logs` |

当前最大上下文 262,144 token、最多 8 个请求槽位均为配置上限。已发布测速覆盖单请求 8K～128K 输入，尚未完成满上下文、并发及完整输出质量验收，也尚无另一台机器完成从零部署的记录。构建与验证范围见 [发布检查](发布检查.md)。
