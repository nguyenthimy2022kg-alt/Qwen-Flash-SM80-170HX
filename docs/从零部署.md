# 从零部署

**简体中文** | [English](DEPLOYMENT.en.md) · [返回首页](../README.md)

v0.2.0 使用固定版本的 NVIDIA 检查点。除克隆仓库外，以下命令均在 Linux 服务主机的仓库根目录执行；仓库不含模型权重或预构建镜像。

## 环境与容量

- Linux x86_64、Python 3.10+、Git、Docker、NVIDIA Container Toolkit 和兼容 CUDA 13 的驱动。
- 验证主机：双 CMP 170HX（SM80，每卡约 64 GiB 显存），约 32 GiB 主机 RAM、8 GiB swap；其他显卡尚未完成整模型验证。
- 原检查点约 132.68 GB，GDS 数据额外约 51.2 GB；同一文件系统上的加载视图使用硬链接，额外约 2.52 GB。保留原文件，建议至少预留 220 GB，Docker 镜像、构建层和缓存另计。跨文件系统时还会复制其他权重，需再预留约 80 GB。
- 容器默认 RAM 限额 21 GiB、RAM＋swap 合计 26 GiB；主机剩余可用内存低于 2 GiB 时启动器停止服务。

## 主机验收条件

双卡 P2P 与 GDS 需分别验证。CMP 可按 [bayley/cmpunlocker](https://github.com/bayley/cmpunlocker/tree/5a7bb4b7e5056306fe49e8b824787659abb19914) 配置 BAR1/P2P，再按 [NVMe GDS 指南](GDS_NVME_P2PDMA_REPRODUCTION.md) 验证禁止 CPU 回退时的 SSD → GPU 读取。无需叠加本仓库的驱动补丁；容器不会自动配置主机驱动。

[参考 H12D 主机](REFERENCE_HARDWARE.md) 没有使用 PCIe switch 转接板。第一张 GPU 负责 PLE 读盘，应根据 SSD/GPU 拓扑选择。已有 P2P/GDS 可用的主机无需重配。

## 1. 下载源码与模型

数据目录须位于通过 GDS 验收的 NVMe 文件系统；若不是主目录所在磁盘，请统一替换下面路径。

```bash
git clone https://github.com/nguyenthimy2022kg-alt/Qwen-Flash-SM80-170HX.git
cd Qwen-Flash-SM80-170HX
python3 -m venv .venv-hf
.venv-hf/bin/pip install 'huggingface_hub==1.29.0'
mkdir -p "$HOME/qwen-flash-data/models"
.venv-hf/bin/hf download nvidia/Qwen3.8-Flash-Next-NVFP4 \
  --revision fc694b54fb0174e0913e6adf86691ef85a4ead47 \
  --local-dir "$HOME/qwen-flash-data/models/NVIDIA-Qwen3.8-Flash-Next-NVFP4" \
  --max-workers 2
```

固定的 [NVIDIA 检查点](https://huggingface.co/nvidia/Qwen3.8-Flash-Next-NVFP4/tree/fc694b54fb0174e0913e6adf86691ef85a4ead47) 包含 NVFP4 主权重、FP8/BF16 混合 MTP 权重及 FP8 PLE；网络中断后重新执行同一命令即可续传。

## 2. 检查模型文件并准备加载视图

```bash
python3 scripts/check-model.py \
  --model "$HOME/qwen-flash-data/models/NVIDIA-Qwen3.8-Flash-Next-NVFP4"
python3 scripts/prepare-nvidia-view.py \
  --source "$HOME/qwen-flash-data/models/NVIDIA-Qwen3.8-Flash-Next-NVFP4" \
  --target "$HOME/qwen-flash-data/models/NVIDIA-Qwen3.8-Flash-Next-GDS"
```

第一条检查固定元数据哈希、所有索引张量的文件头与长度，不表示已校验全部权重内容。第二条从混合分片中提取 MTP 权重和 PLE scale，对复制内容校验，并把 PLE 行排除出加载索引，避免加载时扫描整张查表数据。原检查点保留；目标目录已存在时脚本拒绝覆盖。

## 3. 转换并登记 GDS 数据

```bash
python3 scripts/prepare-ple.py mapping \
  --index "$HOME/qwen-flash-data/models/NVIDIA-Qwen3.8-Flash-Next-NVFP4/model.safetensors.index.json" \
  --output "$HOME/qwen-flash-data/ple-mapping.json"
python3 scripts/convert-ple-to-gds-layout.py \
  --checkpoint-index "$HOME/qwen-flash-data/models/NVIDIA-Qwen3.8-Flash-Next-NVFP4/model.safetensors.index.json" \
  --mapping "$HOME/qwen-flash-data/ple-mapping.json" \
  --output "$HOME/qwen-flash-data/ple-gds" --compact --block-rows 256
python3 scripts/prepare-ple.py enroll \
  --artifact "$HOME/qwen-flash-data/ple-gds" \
  --output config/local-ple-identity.json
```

转换时使用**原检查点索引**，不是加载视图索引。转换按流式读取，不把 51.2 GB 整表装入 RAM；登记默认校验生成数据。已正确转换并校验的 NVIDIA 数据可复用，不能把 RadixArk 的 PLE 与 NVIDIA 权重混用。

## 4. 构建与配置

```bash
docker build -t qwen-flash-sm80:0.2.0 .
cp -n config/example.json config/local.json
python3 - <<'PYCONFIG'
import json
from pathlib import Path
p = Path('config/local.json')
c = json.loads(p.read_text())
root = Path.home() / 'qwen-flash-data'
c.update(image='qwen-flash-sm80:0.2.0', models_root=str(root / 'models'),
         model_subdir='NVIDIA-Qwen3.8-Flash-Next-GDS', ple_artifact=str(root / 'ple-gds'))
p.write_text(json.dumps(c, indent=2) + '\n')
PYCONFIG
```

启动前检查 `config/local.json` 的 `gpu_ids`、路径和 `port`。相对路径从仓库根目录解析。默认 API 和模型名不变。构建时会编译 PCIe 通信模块，无需访问 GPU；运行仍需要可用的 P2P。若 Docker 缺少 buildx，可安装该组件，或使用 `DOCKER_BUILDKIT=0 docker build ...`。

## 5. 启动与接入

```bash
python3 scripts/serve.py start --config config/local.json --dry-run
python3 scripts/serve.py start --config config/local.json
curl --fail http://127.0.0.1:18420/health
curl --fail http://127.0.0.1:18420/v1/models
```

启动器会拒绝同时运行另一套带本项目标签的模型服务。等待加载和预热结束、`/health` 返回 HTTP 200 后再接入。`--dry-run` 只打印命令，不加载模型。日志位于 `runs/<容器名>/`，可用 `docker logs -f <容器名>` 查看启动进度。

| Setting | Value |
|---|---|
| Base URL | `http://127.0.0.1:18420/v1` |
| Model | `qwen3.8-flash-next` |
| API key | `local` (placeholder) |

```bash
curl --no-buffer --fail-with-body http://127.0.0.1:18420/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next","messages":[{"role":"user","content":"写个网站网页"}],"max_tokens":50000,"stream":true}'
```

默认开启思考、`preserve_thinking=true`、`reasoning_effort=xhigh`；温度 1、top-p 0.95、top-k 20。测速可在请求中传 `"temperature":0` 和 `"chat_template_kwargs":{"enable_thinking":false}`。工具解析器为 `qwen3_coder`，请求中传 `tools`、`tool_choice`；客户端负责回传工具结果以及希望保留的思考历史。

每次运行一个活动请求。总上下文上限 262,144 token；输出受 `max_tokens` 和剩余上下文共同限制。图片上限配置为 128 张，实际受上下文和显存限制，视频关闭。前缀按 36 token 匹配，物理块仍为 3,456 token。此版本不要启用异步调度或增加活动请求槽位。

服务仅绑定本机且未配置认证。远程接入可在客户端执行：`ssh -N -L 18420:127.0.0.1:18420 用户名@服务主机`。

### 停止

```bash
python3 scripts/serve.py stop --name "<container>"
```

## 常见启动问题

- PLE/GDS 报错：检查主机直通验收、数据身份、模型与 PLE 是否配套；CPU 回退已关闭。
- 接口未返回 200：查看启动日志和 `error.txt`；提交启动不等于服务就绪。
- `memory-stop.txt`：主机可用 RAM 触发保护，先检查其他负载再重启。
- 模型版本不符：使用固定检查点，不修改原 config/index。
- 输出目录已存在：复用已校验数据，或选择新输出路径并更新身份文件。

## 升级已有部署

加载新版前先停止旧模型。v0.2.0 将默认检查点换为 NVIDIA：**v0.1.7 的 RadixArk 部署需要完成第 1～3 步**，更新模型、PLE 和身份文件路径。保留旧镜像及配置用于回退。已经准备并校验好的 NVIDIA 数据可复用。

```bash
git pull --ff-only
docker build -t qwen-flash-sm80:0.2.0 .
# Update config/local.json paths and image before starting.
python3 scripts/serve.py start --config config/local.json
```

将 `image` 改为 `qwen-flash-sm80:0.2.0`，保留 `draft_int8=true`。旧版单独关闭 `draft_int8` 的方式不适用于新版概率／历史混合草稿路径，启动器会提前拒绝。其余参数位于 `config/vllm-args.json`，修改时保留单请求、同步调度约束。[本版验收范围](发布检查.md)。
