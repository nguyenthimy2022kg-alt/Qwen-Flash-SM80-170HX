# 从零部署

**简体中文** | [English](DEPLOYMENT.en.md)

本文使用固定公开检查点，适用于本项目当前双 SM80 配置。命令在仓库根目录执行，数据目录可按部署环境调整。

## 环境与容量

- Linux x86_64，Python 3.10 或更新版本；以下准备脚本仅依赖 Python 标准库。
- Docker、NVIDIA Container Toolkit，以及兼容 CUDA 13 的驱动。
- 已验证设备为双 CMP 170HX，每卡约 63.39 GiB 显存。两张 40 GB 卡不等价于该配置；其他设备尚未完成整模型验证。
- 测试主机为约 32 GiB RAM 与 8 GiB swap。启动器默认限制容器 RAM 为 21 GiB、RAM＋swap 为 26 GiB；加载时主机还需为其他进程保留空间。
- 模型 safetensors 合计 **135,195,303,851 字节**，GDS 转换额外占用约 **51.2 GB**。建议为模型与转换数据预留至少 **220 GB**；Docker 镜像、构建层和编译缓存另计。
- NVMe、文件系统、驱动与 GPU 拓扑必须支持 GDS；双卡 P2P 需可用。驱动/CMP 支持、PCIe 拓扑与主机 GDS 配置不会由容器自动修复。参考 [NVIDIA GDS 文档](https://docs.nvidia.com/gpudirect-storage/) 与 [Container Toolkit 安装说明](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)。

CMP 设备可参考 [P2P 部署案例](CMP_P2P.md) 和 [GDS NVMe P2PDMA 复现指南](GDS_NVME_P2PDMA_REPRODUCTION.md)。这些文档记录一种已验证的实现方式；部署要求是达到以下运行条件，无需复制参考机器的驱动补丁或系统参数。

实际硬件与接线见 [参考硬件与 PCIe 拓扑](REFERENCE_HARDWARE.md)：单路 EPYC 7532、双 CMP 170HX、990 PRO 4TB；没有使用 PCIe switch 连接显卡和 SSD。

## 主机验收条件

| 检查项 | 必须达到的条件 |
|---|---|
| GPU 与容量 | 两张 SM80 GPU，显存足够容纳当前模型、MTP、缓存与工作区；主机内存和磁盘容量满足加载要求 |
| 软件与模型 | 使用本项目固定软件栈、对应模型 revision 及 PLE 布局，模型检查通过 |
| GPU P2P | 双卡具备所需的读写能力，实际 peer copy 数据校验通过；能力矩阵不能代替实际传输验证 |
| SSD 直读 | 本项目 cuFile 读取路径可用，禁止 compatibility fallback 时仍能正确读入 GPU；结合数据校验与日志确认无 CPU payload 中转 |
| 模型服务 | 完成加载和预热，健康检查通过，并进一步验证实际生成请求 |

驱动补丁、BAR1 配置、IOMMU 模式、NVMe multipath 和文件系统选项由目标硬件及驱动支持情况决定。已有满足条件的环境可以直接准备模型，无需安装 cmpunlocker 或取得参考机器的本地 overlay。需要适配的环境可利用参考资料选择方案，再重新验收。

当前默认 cuFile 配置采用 NVMe P2PDMA。采用其他受支持的 GDS 路径时，需要按该路径核对配置与运行兼容性，并通过同样的 strict 读取验收，不能仅凭“已安装 GDS”判定可用。

功能条件相同不代表性能相同。PCIe 拓扑、带宽、延迟、SSD 和 GPU 性能仍需在目标机器实测；参考吞吐量不是统一验收门槛。当前完整模型仅在文档所列参考硬件验证，不将这些条件视为其他设备已经通过测试的证明。

## 1. 下载源码与模型

```bash
git clone https://github.com/nguyenthimy2022kg-alt/Qwen-Flash-SM80-170HX.git
cd Qwen-Flash-SM80-170HX
python3 -m venv .venv-hf
.venv-hf/bin/pip install 'huggingface_hub==1.29.0'
mkdir -p "$HOME/qwen-flash-data/models"
```

检查点：[RadixArk/Qwen3.8-Flash-Next-NVFP4](https://huggingface.co/RadixArk/Qwen3.8-Flash-Next-NVFP4/tree/7b719225242aacd3dbd3f9407468c2ee9a9d2594)。固定 revision：`7b719225242aacd3dbd3f9407468c2ee9a9d2594`，另记录于 [`config/model-source.json`](../config/model-source.json)。

该版本已包含主模型 NVFP4 权重、31 个 BF16 MTP 张量，以及 128 个 FP8 PLE 张量和 BF16 scale。无需另行量化 PLE，也无需下载第二个 MTP 检查点。模型按其来源许可证使用。

先查看下载计划，再实际下载：

```bash
.venv-hf/bin/hf download RadixArk/Qwen3.8-Flash-Next-NVFP4 \
  --revision 7b719225242aacd3dbd3f9407468c2ee9a9d2594 \
  --local-dir "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4" \
  --dry-run

.venv-hf/bin/hf download RadixArk/Qwen3.8-Flash-Next-NVFP4 \
  --revision 7b719225242aacd3dbd3f9407468c2ee9a9d2594 \
  --local-dir "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4" \
  --max-workers 2
```

网络中断后可重新执行同一条下载命令。不要删除 FP8 PLE 分片；转换和启动前检查仍需这些文件。此流程直接使用下载目录，不需要历史 `.plefp8.bak` 文件或 `create-gds-fp8-checkpoint-view.py`。

## 2. 检查检查点

```bash
python3 scripts/check-model.py \
  --model "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4"
```

检查包括固定 config/index 的 SHA256、206 个 safetensors 文件、索引对应张量与文件长度、31 个 BF16 MTP 张量、PLE dtype/shape/scale，以及 tokenizer 文件是否存在。只读取元数据和文件头，不加载 GPU、不读取完整模型权重。输出中的 `weight_payload_sha256_verified: false` 表示未进行权重内容的全量校验。

需要完整下载内容校验时，可单独执行，耗时取决于存储速度：

```bash
.venv-hf/bin/hf cache verify RadixArk/Qwen3.8-Flash-Next-NVFP4 \
  --revision 7b719225242aacd3dbd3f9407468c2ee9a9d2594 \
  --local-dir "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4" \
  --fail-on-missing-files
```

## 3. 转换并登记 GDS 数据

```bash
python3 scripts/prepare-ple.py mapping \
  --index "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4/model.safetensors.index.json" \
  --output "$HOME/qwen-flash-data/ple-mapping.json"

python3 scripts/convert-ple-to-gds-layout.py \
  --checkpoint-index "$HOME/qwen-flash-data/models/Qwen3.8-Flash-Next-NVFP4/model.safetensors.index.json" \
  --mapping "$HOME/qwen-flash-data/ple-mapping.json" \
  --output "$HOME/qwen-flash-data/ple-gds" --compact --block-rows 256

python3 scripts/prepare-ple.py enroll \
  --artifact "$HOME/qwen-flash-data/ple-gds" \
  --output config/local-ple-identity.json
```

转换以流式方式复制 PLE 数据，不需要把约 51.2 GB 的表完整放入 RAM。`enroll` 默认重读生成数据进行校验；首次部署保留默认校验。映射与身份配置不会覆盖已有同名文件，已有数据可继续使用，无需每次启动重新转换。

## 4. 构建与配置

```bash
docker build -t qwen-flash-sm80:0.1.3 .
cp config/example.json config/local.json
python3 - <<'PY'
import json
from pathlib import Path
p = Path('config/local.json')
c = json.loads(p.read_text())
root = Path.home() / 'qwen-flash-data'
c['models_root'] = str(root / 'models')
c['model_subdir'] = 'Qwen3.8-Flash-Next-NVFP4'
c['ple_artifact'] = str(root / 'ple-gds')
p.write_text(json.dumps(c, ensure_ascii=False, indent=2) + '\n')
PY
```

检查 `config/local.json` 中的 `gpu_ids`；默认 `0`、`1`，也支持完整 GPU UUID。第一张卡为 PLE 读取卡，宜结合 SSD/GPU 拓扑选择。`core_offset_guard` 默认关闭；如需检查偏移，可参阅 [使用说明](使用说明.md)。

当前默认配置为 TEP2、MTP6、全词表草稿 INT8＋BF16 复核；原模型 BF16 草稿权重仍须完整保留。启动配置相对路径以仓库根目录解析。

## 5. 启动与接入

```bash
python3 scripts/serve.py start --config config/local.json --dry-run
python3 scripts/serve.py start --config config/local.json
```

启动器返回容器名和日志目录。首次加载需编译和预热，可用 `docker logs -f "<容器名>"` 查看进度。待以下接口返回 HTTP 200 后接入：

```bash
curl --fail http://127.0.0.1:18420/health
curl --fail http://127.0.0.1:18420/v1/models
```

| 客户端配置 | 值 |
|---|---|
| 协议 | OpenAI 兼容 |
| Base URL | `http://127.0.0.1:18420/v1` |
| 模型 | `qwen3.8-flash-next` |
| API Key | 未配置认证；客户端必填时可填 `local` |

端口仅绑定本机。异机客户端可通过 SSH 转发访问：

```bash
ssh -N -L 18420:127.0.0.1:18420 用户名@服务主机
```

随后在客户端机器使用相同 Base URL。容器内客户端的 `127.0.0.1` 指向自身，需自行配置到宿主机的网络路径。

停止服务：

```bash
python3 scripts/serve.py stop --name "<容器名>"
```

## 常见启动问题

| 现象 | 排查位置 |
|---|---|
| 找不到模型或 PLE 文件 | 下载是否完整、`model_subdir` 与挂载路径、PLE 转换与登记是否完成 |
| 固定模型版本不一致 | 是否使用了指定 revision，是否手动修改过 config/index |
| cuFile/GDS 注册或读取失败 | 主机 GDS、文件系统和拓扑；当前 `allow_compat_mode=false` 不使用主机中转回退 |
| 停止后生成 `memory-stop.txt` | 主机可用 RAM 触发保护，先检查其他进程与 swap 配置 |
| 提示 image 不存在 | 先执行 Docker 构建，确认 image 标签与 `config/local.json` 一致 |
| `/health` 尚未返回 200 | 查看加载/编译日志及 `runs/<容器名>/error.txt`；启动提交不等于服务就绪 |

完整验证边界见 [发布检查](发布检查.md)。当前已验证本机启动，尚无另一台机器完成从零部署的记录。
