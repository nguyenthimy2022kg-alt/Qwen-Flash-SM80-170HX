# 使用说明

## 适用范围

当前针对双 CMP 170HX（SM80）的 Qwen3.8-Flash-Next NVFP4 主模型、BF16 草稿及 FP8 PLE 布局。MTP 深度固定为 6；草稿 INT8 专用形状为每卡 `[124160,2560]` 词表、输入一行，其他行数走原完整打分。其他模型与 TP 配置需要额外适配。

启动参数中保留 262144 最大模型长度和最多 8 请求槽位，这些参数为配置上限，**满长度与多请求并发尚未完成验收**。性能记录主要是单请求写网页。

主机需要支持 GDS 的 NVMe/文件系统、驱动和拓扑，cuFile 必须成功建立直通。项目不自动修改驱动、PCIe、显卡频率、风扇或功耗。

## 构建

在仓库根目录运行：

```bash
docker build -t qwen-flash-sm80:0.1.3 .
```

Dockerfile 固定公开基础镜像，安装 cuFile 1.15.1.6、CUDA Driver 开发头文件 13.0.96、TileLang 0.1.14、apache-tvm-ffi 0.1.12，编译 GDS C++ 扩展，再校验并覆盖增量 Python 源码。原有 vLLM 二进制算子继续使用基础镜像版本。

可用 `--build-arg PIP_INDEX_URL=所选依赖源` 指定下载来源。两个编译依赖仍按 `requirements-kernels.txt` 中的 PyPI 官方 SHA256 校验；也支持为已校验的本地 wheel 缓存提供索引。默认使用 PyPI。

这是版本绑定的增量包；更换基础镜像时需要重新验证源码兼容性。上游包中 Marlin 打包接口、编译器生成代码和预加载 ABI 都属于兼容要求。

## 模型与 PLE 数据

新部署使用 [从零部署](从零部署.md) 中固定的 RadixArk 检查点，包含所需 NVFP4 主模型、BF16 MTP 和 FP8 PLE；以下为数据格式与独立准备命令。

需要自行准备含 MTP 权重的对应模型。当前 PLE 要求为 **128 个 F8_E4M3 分片、合计 320001536 行、每行 160 字节，以及一个 BF16 全局 scale**。NVFP4 主模型不代表 PLE 也是 NVFP4；只拿到另一种 PLE 格式的检查点不能直接启动。

已有正确 FP8 PLE 检查点时，可仅读取文件头生成映射：

```bash
python3 scripts/prepare-ple.py mapping \
  --index /data/models/模型目录/model.safetensors.index.json \
  --output /data/ple-mapping.json
python3 scripts/convert-ple-to-gds-layout.py \
  --checkpoint-index /data/models/模型目录/model.safetensors.index.json \
  --mapping /data/ple-mapping.json --output /data/ple-gds --compact --block-rows 256
python3 scripts/prepare-ple.py enroll \
  --artifact /data/ple-gds --output config/local-ple-identity.json
```

转换会额外写入约 51.2 GB 的 PLE 数据，需要预留空间；不修改原始权重。登记默认校验完整数据文件，生成该数据版本的身份配置。映射和登记均不覆盖已有输出文件；重复运行时请指定新文件名，脚本会在读取数据前检查输出路径。已有经过完整校验的转换数据，可用 `--metadata-only` 跳过重复读取；它不会重新证明数据内容未损坏。

`create-gds-fp8-checkpoint-view.py` 是历史 FP8 备份布局的视图工具，要求已有 `.plefp8.bak` 和 `_off_plefp8` 文件；它不是通用量化转换器。已有完整 FP8 PLE 检查点时无需使用该工具。

`models_root` 应覆盖模型视图和符号链接指向的实际权重目录。例如模型视图引用同级目录的权重，应挂载共同父目录。容器内无法访问挂载范围外的符号链接目标。

## 配置与启动

```bash
cp config/example.json config/local.json
```

| 配置 | 含义 |
|---|---|
| `models_root` / `model_subdir` | 模型父目录与其中的模型目录，父目录会只读挂载到 `/models` |
| `ple_artifact` | 已转换 GDS 数据根目录，应含 `CURRENT` |
| `ple_identity` | 登记脚本生成的数据身份 JSON |
| `gpu_ids` | 两张显卡的编号或完整 UUID；顺序决定 rank，第一张承担读取 |
| `mode` | 默认 `tep2`；可选 `tp2` |
| `draft_int8` | 默认 `true`；设为 `false` 回退原草稿完整词表打分及原汇总路径，保留 MTP6 |
| `port` | 默认 18420，仅本机监听 |
| `container_memory_gib` | 默认 21 GiB 主机内存上限，不是显存上限 |
| `container_memory_and_swap_gib` | 默认 26 GiB，内存加交换空间总上限 |
| `min_host_available_gib` | 默认主机剩余可用内存低于 2 GiB 时停止服务 |
| `core_offset_guard` | 默认空；需要检查 GPU 核心偏移时配置 `{"gpu_uuid":"完整UUID","expected":0}`，只检查不修改 |
| `validation_dir` | 可选的草稿验证输入目录，默认空；未配置时跳过历史样本校验 |

```bash
python3 scripts/serve.py start --config config/local.json --dry-run
python3 scripts/serve.py start --config config/local.json
```

`--dry-run` 读取显卡编号/UUID/PCI 总线标识并打印命令，不加载模型，也不验证数据文件是否存在。正式启动会先检查必填路径及文件/目录类型，检查通过后才提交容器启动。启动后日志保存在 `runs/容器名/`；用 `docker logs -f 容器名` 观察加载。内存保护触发会写入 `memory-stop.txt`。

服务健康检查：

```bash
curl http://127.0.0.1:18420/health
```

请求示例：

```bash
curl http://127.0.0.1:18420/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next","messages":[{"role":"user","content":"写个网站网页"}],"temperature":0,"seed":0,"max_tokens":32768,"stream":true}'
```

模型可能输出思考内容，实际结束长度和速度随生成内容变化。容器使用自己的编译缓存，第一次加载/预热不计入 decode 成绩。

## 回退与停止

先停止现有服务，再把 `draft_int8` 改为 `false` 重新启动，可以回到保留其他优化的原 MTP6 草稿打分路径。`mode=tp2` 仅改变专家分工配置，其他优化保持启用。

```bash
python3 scripts/serve.py stop --name "<容器名>"
```

停止器只操作带有本项目标签的容器，不主动删除其他服务。后台监控进程在容器退出后结束。

## 验证范围

170.826 tok/s 来自发布打包前的单次整模型测试。发布版将路径、GPU 标识、PLE 校验信息和历史样本验证参数化，保留核心计算实现。已加载的发布服务随后完成 8K～128K 输入、输出上限 50,000 token 的五档单请求测试，均自然结束；客户端 decode 速度为 151.05～168.29 tok/s。构建与源码一致性见 [发布检查](发布检查.md)，测速条件见 [性能记录](性能记录.md)。
