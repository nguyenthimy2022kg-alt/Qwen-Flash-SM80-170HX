# 配置与运行参考

[返回首页](../README.md) · [首次部署](从零部署.md) · [English](DEPLOYMENT.en.md)

v0.2.0 默认 NVIDIA NVFP4 检查点、双 SM80 TEP2、单个活动请求、同步调度。MTP 普通草稿长度为 6，历史文本匹配草稿最长 32；不要将配置中的 32 改成 6，这个数值是两条路径的共同容量。

## 配置与启动

| 文件／字段 | 用途 |
|---|---|
| `config/local.json` | 本机路径、镜像、端口与 GPU 顺序，复制 `example.json` 后填写 |
| `models_root` / `model_subdir` | 模型父目录及第 2 步生成的 NVIDIA 加载视图 |
| `ple_artifact` / `ple_identity` | 与 NVIDIA 权重配套的 GDS 数据及登记文件，不能混用旧 RadixArk 数据 |
| `gpu_ids` | 两张不同显卡的编号或 UUID；第一张负责读盘 |
| `mode` | 默认 `tep2`；`tp2` 关闭专家并行，发布验收采用 `tep2` |
| `draft_int8` | 当前混合草稿要求为 `true`，不能使用旧版的独立关闭开关 |
| `port` | 默认 18420，只绑定本机 |
| `container_memory_gib` | 容器 RAM 限额，默认 21 GiB，不是显存限额 |
| `container_memory_and_swap_gib` | RAM＋swap 总限额，默认 26 GiB |
| `min_host_available_gib` | 主机剩余可用 RAM 保护阈值，默认 2 GiB |
| `config/vllm-args.json` | 推理参数；单请求、同步调度、草稿容量 32 是当前实现约束 |
| `config/runtime-env.json` | GDS、读盘线程和运行优化开关 |

启动与停止：

```bash
python3 scripts/serve.py start --config config/local.json
python3 scripts/serve.py stop --name "<容器名>"
```

默认上下文 262144，默认输出上限 262144，输入＋输出不能超过总上下文。支持工具解析和图片输入；128 张是配置上限，实际容量取决于图片尺寸、上下文和显存。前缀匹配单位 36 token，物理缓存块 3456 token。

默认开启思考并保留思考历史，模板档位 `xhigh`，温度 1、top-p 0.95、top-k 20。测速时可在请求中关闭思考并设置温度 0。客户端需要正确回传历史消息和工具结果，服务参数不能代替客户端保存历史。

## 构建与数据

固定基础镜像、cuFile、TileLang 与 TVM FFI 版本，不更新整套 vLLM。覆盖上游源码前先验证哈希；新增 PCIe 通信模块根据随仓库发布的 FlashInfer 固定源码编译，不需要本机实验目录。

`prepare-nvidia-view.py` 从 NVIDIA 混合分片中分离 PLE，保留并校验其他张量；原始权重不修改。PLE 转换使用原检查点索引，按流式复制后登记身份。完整步骤见[部署指南](从零部署.md)。

## 停止与回退

停止服务后，容器占用的模型显存释放，镜像和数据仍保留。后台内存保护进程随容器停止结束。升级前保留上一版镜像与配套配置；回退时恢复整套匹配的配置、模型和 PLE 身份，不只修改一个草稿开关。

异常时查看 `runs/<容器名>/` 和 `docker logs`。`memory-stop.txt` 表示主机剩余 RAM 触发保护。不要在旧模型仍运行或卡住时再次加载一套模型。

本版实测范围见[发布检查](发布检查.md)；历史测速见[性能记录](性能记录.md)。
